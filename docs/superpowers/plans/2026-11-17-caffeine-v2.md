# Caffeine v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tile cycling, ∞ mode with battery guard, auto-stop guards, +5 min extend, shortcuts, and a Material 3 Expressive main screen.

**Architecture:** Pure session logic (`SessionLogic.kt`) is unit-tested on the JVM; `CaffeineController` mutates a process-wide `StateFlow<Session?>` and drives `CaffeineService`, which owns the wake lock, the dynamic guard receivers and the notification. The tile, shortcuts, notification and UI all go through the controller. UI is split into small composable files under `ui/`.

**Tech Stack:** Kotlin 2.2.10, AGP 9.5.1, Compose BOM 2026.09.00, material3 1.5.0-rc01 (Expressive), JUnit 4.

**Spec:** `docs/superpowers/specs/2026-11-17-caffeine-v2-design.md`

## Global Constraints

- minSdk 24, targetSdk 37; no new permissions in the manifest.
- `androidx.compose.material3:material3` pinned to `1.5.0-rc01`; everything else from BOM `2026.09.00`.
- Every user-visible string exists in both `values/strings.xml` (en) and `values-vi/strings.xml`.
- No periodic background work: no polling, no tickers outside the visible Activity. Receivers are registered only while the service runs.
- Tile cycle is exactly: Off → 10 → 15 → 20 → ∞ → Off.
- Custom duration range 1–120 min. Extend step 5 min.
- Defaults: `stopOnScreenOff = true`, `stopOnUnplug = false`, `dimScreen = false`.
- Unit tests run with: `.\gradlew.bat :app:testDebugUnitTest` (from `E:\Code\Caffeine`).

## Review Focus

1. Tapping "+5 min" on a stale notification after the session already ended → must not start a session; service stops itself. (Test: `extendedBy` on an expired session, Task 2; service no-op path, Task 3.)
2. Starting Caffeine while battery is already low and unplugged → refuse, show a toast, tile stays off. (Test: `isBatteryLow`, Task 2.)
3. Corrupted / out-of-range stored duration (e.g. 0, 999, -7) → falls back to a valid duration instead of crashing. (Test: `decodeDuration`, Task 2.)
4. Tapping the tile while a custom (e.g. 35 min) session from the app is running → goes Off, not to an arbitrary step. (Test: `TileCycle.next`, Task 2.)
5. Rapid repeated tile taps / extends → wake lock is replaced, never stacked; exactly one pending timeout. (Manual check, Task 3 Step 6.)

  - `data class Session(val startAt: Long, val endAt: Long?, val duration: Duration)` — `endAt == null` ⇔ ∞

  - `const val EXTEND_MINUTES = 5`, `val CUSTOM_RANGE = 1..120`, `val PRESET_MINUTES = listOf(10, 15, 20)`
  - `fun isBatteryLow(level: Int, scale: Int, plugged: Int, lowFlag: Boolean?): Boolean` — false if `plugged != 0`; else `lowFlag` if non-null, else `level * 100 / scale <= 15`
- Produces (`Prefs.kt`): `object Prefs` with `selected(ctx): Duration` / `setSelected(ctx, Duration)` (stored via `encode`/`decodeDuration`, default `Minutes(10)`), and Boolean get/set pairs `stopOnScreenOff` (default true), `stopOnUnplug` (false), `dimScreen` (false), `tileAdded` (false). Booleans also exposed as `StateFlow<Boolean>`s is NOT needed; UI reads once and writes through.

  - `object CaffeineController { fun isActive(): Boolean; fun start(ctx: Context, duration: Duration); fun stop(ctx: Context); fun extend(ctx: Context); fun cycle(ctx: Context); fun toggle(ctx: Context) }` — `toggle` starts `Prefs.selected` or stops; `cycle` = `TileCycle.next(current?.duration)` then start or stop; `extend` sends `ACTION_EXTEND` to the service.
  - `start` checks the sticky `ACTION_BATTERY_CHANGED` intent with `isBatteryLow` (pass `BatteryManager.EXTRA_BATTERY_LOW` only on API 28+, else null); if low → `Toast(R.string.low_battery)` and return without changing state.
  - Service intent extras: `EXTRA_DURATION: Int` (encoded), `EXTRA_START_AT: Long`; actions `ACTION_STOP`, `ACTION_EXTEND` (`com.laffy.caffeine.STOP` / `.EXTEND`).

- [x] **Step 1:** Rewrite controller/state per Interfaces. `start` sets `session` to `duration.toSession(now)` then `startForegroundService` with extras; on exception resets to null.
- [x] **Step 2:** Service `onStartCommand`:
  - `ACTION_STOP` → `CaffeineController.stop`.
  - `ACTION_EXTEND` → `CaffeineState.session.value?.extendedBy(EXTEND_MINUTES, now)`; null → `stopSelf()` and return (Review Focus 1); else store it and re-arm.
  - otherwise rebuild `Session` from extras and arm.
  - "Arm" = `startForeground(notification)`, (re)create the wake lock with level `SCREEN_DIM_WAKE_LOCK` if `Prefs.dimScreen` else `SCREEN_BRIGHT_WAKE_LOCK` (recreate if level changed, release old), `acquire(remaining)` for timed / `acquire()` for ∞, `handler.removeCallbacks(timeout)` then `postDelayed` only for timed, `CaffeineTileService.requestUpdate`.
- [x] **Step 3:** Guards: in `onCreate` register one receiver (`ContextCompat.registerReceiver`, `RECEIVER_NOT_EXPORTED`) for `ACTION_SCREEN_OFF`, `ACTION_POWER_DISCONNECTED`, `ACTION_BATTERY_LOW`; unregister in `onDestroy`. Stop when: screen off && `Prefs.stopOnScreenOff`; unplugged && `Prefs.stopOnUnplug`; battery low always.
